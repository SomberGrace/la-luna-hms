# Frontend Design Engineering

## Workflow

1. Identify the user, primary task, content hierarchy, and target screen sizes before choosing visual treatments.
2. Inspect the existing application, design system, assets, and component conventions. Preserve established patterns where consistency matters.
3. Define a coherent visual direction: meaningful typography, a deliberate color palette, layout rhythm, and a small set of complementary details.
4. Make the interface distinctive through composition and hierarchy—not decoration that competes with the task. Avoid generic templates and decorative effects without a product purpose.
5. Implement responsive layouts and clear interaction states, including loading, empty, error, focus, and disabled states when relevant.
6. Add restrained, purposeful motion for feedback and continuity. Prefer transform and opacity animations, short durations, interruptible interactions, and reduced-motion support; avoid animation that delays or obscures the task.
7. Check keyboard operation, semantic structure, readable contrast, and reduced-motion preferences.
8. Run the most relevant project checks and, when available, inspect the rendered UI at desktop and narrow viewport widths.

## Design Standards

- Avoid default-looking layouts, repetitive card grids, arbitrary gradients, and excessive decoration unless they fit the product's purpose.
- Use existing assets and components where appropriate; do not introduce a new visual system without a reason.
- Keep actions understandable and content legible. Visual novelty must not reduce accessibility or usability.
- Scope changes to the requested interface and preserve existing behavior unless a behavior change is requested.
